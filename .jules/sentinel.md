## 2025-06-09 - Add Missing Default Security Headers for SSR
**Vulnerability:** Missing security headers (`X-Content-Type-Options`, `X-Frame-Options`, `X-XSS-Protection`) in SSR HTML responses.
**Learning:** In a React Router v7 application using Cloudflare Workers, the default `entry.server.tsx` doesn't include common security headers by default. These headers must be manually added to the `responseHeaders` object before constructing the final `Response`.
**Prevention:** Always verify that fundamental security headers like `X-Content-Type-Options: nosniff` and `X-Frame-Options: DENY` are applied at the global entry point (`entry.server.tsx`) to protect all HTML responses across the application.
## 2023-10-27 - HSTS Implementation and SameSite Caveats
**Vulnerability:** Missing `Strict-Transport-Security` header allows SSL downgrade attacks. Attempting to lock down session cookies to `SameSite=Strict` breaks OAuth flows.
**Learning:** We need to apply HSTS globally in SSR entry points to ensure browsers only connect via HTTPS. However, we MUST NOT change the session cookie to `SameSite=Strict` when using an OAuth flow (like Google login). If the session cookie is `Strict`, it will not be sent with the cross-site GET/POST redirect from the OAuth provider back to our callback, breaking the authentication flow and external link entry points. Session cookies must remain `SameSite=Lax` for these flows to work.
**Prevention:** Apply HSTS (`Strict-Transport-Security`) globally in SSR entry points. Always maintain `SameSite=Lax` for session cookies involved in cross-site OAuth flows to preserve functional entry points.
